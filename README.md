# NowPlaying HUD

Резидентна утиліта для Windows: компактний HUD у куті екрана поверх усього,
який показує поточний трек із будь-якого джерела, зареєстрованого в SMTC,
і дозволяє ним керувати — не виходячи з гри.

Не стрімить музику. Не має бібліотеки. Робить одну річ.

---

## Збірка

```bash
dotnet build NowPlayingHud.sln -c Release
dotnet run --project src/NowPlayingHud
```

Потрібен **.NET SDK 10**. Нижче не збереться: `H.NotifyIcon.Wpf 2.4.1` містить
рівно два таргети — `net462` і `net10.0-windows`.

Публікація:

```bash
dotnet publish src/NowPlayingHud -p:PublishProfile=win-x64
```

Профіль лежить у `Properties/PublishProfiles/win-x64.pubxml`: self-contained,
ReadyToRun, win-x64. Тримати `RuntimeIdentifier` і `SelfContained` у самому
`.csproj` не варто — тоді кожен `dotnet build` починає копіювати весь рантайм.

Trimming і NativeAOT з WPF не працюють — не витрачай на них час.

## Спочатку — кроки 1–3

Порядок розробки з концепції: перші три кроки перевіряють життєздатність.
Мають зайняти один-два вечори. Якщо крок 3 провалиться на реальних іграх,
краще дізнатись це зараз.

**Крок 1–2** — `tools/SmtcProbe`, консольний застосунок без WPF:

```bash
dotnet run --project tools/SmtcProbe
```

Друкує список медіасесій і поточний трек, реєструє Alt+Shift+M і друкує стан
при натисканні. Запусти Spotify, потім переключись у гру і натисни хоткей.
Якщо в консолі порожньо — далі йти нема сенсу.

**Крок 3** — запусти основний застосунок, зайди в гру, натисни Alt+Shift+M.
Оверлей має з'явитись поверх. Якщо гра в **ексклюзивному** фулскріні — не
з'явиться, і це очікувано (див. «Відомі обмеження»).

## Стан коду

| Частина | Стан |
|---|---|
| `Media/SmtcService` | працює: сесії, метадані, обкладинка, таймлайн, керування, закріплення джерела |
| `Input/HotkeyService` | працює: RegisterHotKey на message-only вікні, hold-to-peek через опитування |
| `Overlay/*` | працює: стилі вікна, click-through, позиціонування по кутах з урахуванням DPI, анімації |
| `Settings/*` | працює: JSON, відкладений запис, розділення шляхів exe/MSIX, автозапуск |
| `Configuration/SettingsWindow` | працює: шість пунктів, застосування на льоту |
| `Tray/TrayIconHost` | працює |
| `Media/SourceIconProvider` | працює: логотип MSIX-пакета або іконка exe, вічний кеш за AUMID |
| Зовнішній вигляд | базове полірування зроблено: обрис 8%, тінь, бейдж джерела, порожній стан |

**Тінь треба заміряти.** `DropShadowEffect` — це піксельний шейдер, який
перемальовується щокадру разом з анімацією прогресу. Якщо в грі просідає fps,
прибрати `Border.Effect` в `OverlayWindow.xaml` і покласти під картку
статичний `RadialGradientBrush`.

## Архітектура

Один проєкт, плоска структура. Ніякої Clean Architecture: для ~3000 рядків
шари й інтерфейси не дадуть нічого, крім написання інтерфейсів.

Два винятки, обидва обґрунтовані:

1. **`ISettingsStore`** — шлях зберігання реально відрізняється між звичайним
   exe (`%LOCALAPPDATA%`) і MSIX (`ApplicationData.Current.LocalFolder`,
   файлова система віртуалізується).
2. **`SmtcService` не знає про WPF** — не заради чистоти, а щоб перевіряти
   його консольним застосунком, поки оверлея ще не існує. Це ж стане швом для
   майбутнього Linux-порту: на його місце стане `MprisService`.

Ключові технічні рішення прокоментовані прямо в коді, у місцях, де вони
приймаються.

## Відомі обмеження

| Що | Чому | Що з цим робити |
|---|---|---|
| Ексклюзивний фулскрін | topmost-вікно там просто не малюється | нічого. Хук на `IDXGISwapChain::Present` = інжект у чужий процес = бан від EAC/BattlEye/Vanguard. Підтримуємо borderless/FSO — це більшість сучасних ігор |
| Гра запущена від адміна | UIPI не пропускає хоткеї до непідвищеного процесу | або `requireAdministrator` у `app.manifest`, або чесний рядок у FAQ |
| Зайнятий хоткей | `RegisterHotKey` мовчки повертає `false` | обробляється: конфлікти показуються у вікні налаштувань |
| Джерела без SMTC | частина Electron-застосунків не реєструє сесію; AIMP потребує плагіна | задокументувати |
